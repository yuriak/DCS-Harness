# In-game player communication

The resident **f10** plugin provides a bounded Agent-to-player channel inside
DCS. It sends scoped text, owns its current-session menu registrations, and
projects matching DCS-gRPC command events into a small acknowledgeable input
view. It does not choose wording, tactics, scenario branches, or narrative.

## Lifecycle

The plugin autostarts with the resident runtime so it can observe session and
event-ledger changes. Autostart does not alter the F10 menu. An explicit
`init` creates one `DCS-Harness` root for the selected mission, coalition, or
group scope and, by default, a `Request Director Attention` Player Ping command.

A new DCS-gRPC session invalidates every registered path and all local input
state. The plugin does not replay old menus or interactions. Re-establish only
the current scenario's required communication after normal live preflight.

## Discover and operate

Inspect `plugins describe f10` for the exact current argument contract. The
operations are:

- `status`: detailed bounded state and Harness-owned registration summaries;
- `send`: mission, coalition, or group in-game text;
- `init`: explicitly create a scoped root and optional default Player Ping;
- `add-menu` and `add-command`: add descendants below a returned registered
  menu ID;
- `remove` and `clear`: remove only Harness-registered items;
- `recent`: newest-first current-session player selections, optionally pending
  or interaction-filtered;
- `ack`: mark handled selections by their session-qualified input IDs.

Group text takes the numeric DCS group ID used by TriggerService. Group menu
operations take the group name required by MissionService. Do not substitute
one for the other.

## Structured choices

Every command carries a stable interaction ID and choice ID. Optional action
and small JSON data are returned as factual context; they are not executable
callbacks. The plugin accepts only events carrying its fixed source marker and
matching a command registered in the current process, scope, and session.
The pinned command events identify mission/coalition scope and, for group
commands, the group; they do not identify the individual player who clicked.
The input therefore leaves player identity null rather than inferring it.

`recent` is a bounded runtime view over command facts already preserved by the
events ledger. Acknowledgement changes only the local pending view; it does not
rewrite factual event history. Overflow remains visible in status, and the
ledger is the durable current-session chronology.

## Safety and current verification status

**2026-09-05 HIL, DCS 2.9.29.27468:** Group text, menu creation, two
clicks, acknowledgement and removal were observed successfully. Same-session
Harness restart left the old menu visible but unregistered; a differently named
new root worked. Mission reload cleared the old menu, but the input cursor
retained its old value (4): new-session click event 3 existed in events while
`f10 recent` stayed empty. Until repaired, do not infer no click from an empty
input view after reload. Inspect bounded command events without a group filter
(that filter also omitted a witnessed group-command row in this run). These
are measured limitations, not permission to replay menus or clicks blindly.

**Post-HIL revision, live reverified 2026-09-05 on DCS 2.9.29.27468:**
Foreign-session ledger rows no longer advance the input
cursor. Group-command filters now read the factual group payload. Graceful
shutdown removes registered roots when DCS remains reachable and logs cleanup
failures. A focused live run advanced the old-session cursor, reloaded the
mission, observed the new cursor reset to zero, and received new-session command
event ID 1 through both `f10 recent` and a group-filtered events query. Human
inspection also confirmed the registered root disappeared on graceful stop.
Forced termination
or disconnected DCS can still leave orphan menus; no ownership replay exists.

Use the narrowest audience. Avoid mission-wide spam, clear only Harness-owned
roots, and remove completed dynamic interactions. The plugin never accepts an
arbitrary Lua callback.

The typed group-menu path performs a server-side group-name lookup. The HIL
verified tested active and late groups, not every dynamic spawn timing.
Preserve typed failures and do not silently add a Lua fallback.

Registration ownership is currently process-local. If Harness itself restarts
without a new DCS session, do not assume pre-restart menus were recovered or
remain manageable. Graceful cleanup is best effort; crash recovery remains
unsupported.
